# Brand images

These are **not** used by the integration at runtime. Home Assistant and HACS do
not read icons out of a custom repository — they fetch them from
`brands.home-assistant.io`, which is served from the
[home-assistant/brands](https://github.com/home-assistant/brands) repository.

Until the images below are merged there, HACS shows an automatically generated
placeholder. You can check the current state at any time:

```bash
curl -o /dev/null -w '%{http_code}\n' https://brands.home-assistant.io/netviz/icon.png
```

`404` means there is no brand yet. Note that the `/_/netviz/icon.png` path always
answers `200` — that is the generated fallback, not a real icon.

## Files

| File | Size | Purpose |
|---|---|---|
| `icon.png` | 256×256 | square icon, the one HACS and the integrations list show |
| `icon@2x.png` | 512×512 | hDPI variant |
| `logo.png` | 480×160 | landscape logo |
| `logo@2x.png` | 960×320 | hDPI variant |

All four are regenerated by `gen_icon.py`, so the design lives in code rather than
in a binary nobody can edit:

```bash
pip install Pillow
python brand/gen_icon.py
```

The design reuses the card's colour language — green 1G, blue 10G, amber 10/100M,
grey down, orange PoE — so the icon, the faceplate card and the documentation all
say the same thing.

## Submitting them

1. Fork `home-assistant/brands`
2. Copy these four files into `custom_integrations/netviz/`
3. Open a pull request

The domain directory must match `domain` in `manifest.json`, which is `netviz` —
not the repository name. Requirements the review checks: PNG, square icons at
exactly 256×256 and 512×512, landscape logos with the shortest side between
128–256 and 256–512, transparency preferred, trimmed to the minimum amount of
empty space, losslessly optimised, and no Home Assistant branding in the artwork.
